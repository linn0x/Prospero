版本：1.0\
配套主方案：[Prospero 稳定运行完整改造规划](prospero-runtime-reliability-plan.md)\
状态：原始工作包与验收基线；当前进度见[实施与验收记录](prospero-runtime-reliability-implementation.md)，本文件不代表生产发布已获执行窗口

## 1 下发方式

先下发 W00，再由负责人冻结 W01 契约。W09 可同时搭建隔离故障测试。契约冻结后分批下发 W02 至 W08，按依赖合并。每个 Agent 必须同时收到主方案、本文件的通用约束和自己的工作包，不能仅凭任务标题实施。

建议独立工作区。若当前工作区有未提交内容，使用经用户允许的工作区方式保留这些内容；不得 reset、清理未跟踪文件或替换已有设计文档。遵守实际 AGENTS.md，未获得明确要求时不主动提交或推送。

### 1.1 可并行批次

| 批次 | 工作包 | 说明 |
| --- | --- | --- |
| A | W00、W09 的测试基建部分 | 基线和 fake executor 可以并行；先不改变公共协议 |
| B | W01 | 冻结身份、状态、存储和接口，提供 fake Host 契约 |
| C | W02、W03、W05、W06 的独立模块 | 依赖 W01；W05/W06 先用 fake execution，不假装完成集成 |
| D | W04、W07、W08 | W04 集成生命周期；W07/W08 可先围绕冻结接口开发 |
| E | W00、W09 | 完整集成、跨平台验收、迁移、长跑和发布证据 |

W00 是集成责任，不意味着其他 Agent 可以把未完成闭环全部转交给它。每个工作包必须交付自己负责功能的可执行测试和完整接线要求。

### 1.2 所有 Agent 的共同约束

1. 本次只改造 Prospero 的通用稳定运行能力，不开展特定 Harness 接入，不改模型和调用方业务判定。
2. 先确认当前源码及已有能力。已有持久启动队列、事务事件、activity API 和数据库背压必须复用。
3. 严格遵守主方案 I01 至 I14。不能以超时、心跳丢失或 UI 终态推断进程已退出。
4. 不新建竞争的业务 DAG、资源真值或物理执行账本。不直接改生产数据库修状态。
5. 公共字段、schema 序号、错误码、capability 和迁移由 W01 统一；共享入口由 W00 集成。
6. 关键事实绑定 task、attempt、execution epoch、Host 身份和操作 ID。不能只传 session ID 或 PID。
7. 每种重试必须说明由谁负责、预算是什么、是否会产生新 attempt，以及遇到未知外部效果怎么办。
8. 测试使用隔离 home、临时仓库、测试专用进程和 fake executor。不得 kill 现有 daemon、用户会话或生产 Worker。
9. 不修改实际线上配置，不启动真实业务测试，不创建新的自动化任务。生产实施遵循实际下发授权和发布安排。
10. 代码变更完成后运行适当测试、lint 和 typecheck。既有失败要与新增失败分开列出，不能声称全绿。
11. 无法完成依赖时提供明确契约缺口和可验证的局部产物，不能用桩实现冒充完成。
12. 对已实现部分发现与规划不同的事实，先通知 W00 修正范围，不自行放宽验收要求。

## 4 W02 独立执行宿主与平台进程所有权

### 职责与文件归属

实现独立 Execution Host、私有 IPC、命令和事件日志、身份认证、重连和退出证明。建议新增 `apps/daemon-rs/src/execution_host/` 模块及宿主入口；最终路径由 W00 冻结。已有 TS supervisor、Windows Host 作为实现和测试参考，不直接复制旧兼容假设。

### 必须交付

- Host 生命周期与版本握手；daemon detach 时保持执行，shutdown 不等同于 kill。
- Unix 和 Windows 的平台能力实现；不能声称一次 macOS 测试证明 Windows 退出语义。
- Host epoch、启动身份和受控进程树记录，避免 PID 复用误附着和误杀。
- 持久命令去重和查询，事件按序落盘后通知；同 ID 不同参数冲突。
- pending approval/question 的原 request ID 保留与重连，无隐式批准。
- Worker 的稳定控制入口和离线交付 RECEIVED 回执，daemon 恢复后按原操作补交，不伪装业务验收成功。
- 严格退出证明和日志排空；子进程清理范围与能力限制可查询。
- Host 日志写失败、磁盘压力、启动失败和父进程异常退出时的有界行为。
- 升级保留旧 Host/runtime 的能力，声明新旧协议兼容范围。

### 验收

覆盖 I03/I06/I07/I09/I10 与 F02/F03/F07 至 F13/F19/F23/F29。实际启动测试专用宿主并杀掉测试 daemon，确认同一个 Host 继续运行且事件可重放；只测 mock 状态迁移不够。

### 边界

不改 Task 业务结论，不实现调度器，不改现有终端渲染。不能通过直接保留 PID 而丢掉协议所有者来宣称可恢复。平台暂不支持能力时显式降级或阻止启用，不能把 direct 模式伪装成受托管模式。

### 可直接下发的任务

> 你负责 W02 独立 Execution Host。按冻结的 W01 协议实现可跨 daemon 重启存活的执行宿主，持有 Driver 与受控进程、命令去重日志、事件序号和 pending interactions。复用既有 supervisor/Windows Host 中已验证的边界，交付平台身份校验、停止证明、重连、日志失败处理与真实隔离进程测试。不得操作正在运行的用户 daemon，不得把心跳失联等同于进程退出，不得自动重发无法确认外部效果的命令。

## 5 W03 Driver 生命周期与结构化错误

### 职责与文件归属

负责 `apps/daemon-rs/src/agent/` 下各 Driver 的统一生命周期边界和错误映射。`runtime.rs` 共享接线交 W00；优先新增公共生命周期和错误模块，再逐个适配已有 Driver。覆盖当前已支持后端，避免只为一个后端实现完整语义。

### 必须交付

- 统一 create、send、observe、interrupt、terminate、await_quiescence 能力及其异步返回语义。
- 启动资源守卫：每个失败出口均有明确进程与句柄归属；不能因 `?` 提前返回遗留进程。
- 取消与停止分别返回接收、执行、退出确认，不能 fire-and-forget 后报成功。
- 结构化错误分类、阶段、retry-after 和诊断引用；保留后端原始错误证据。
- 用量事件的完整性与结算标记，重复事件去重，未知用量不填零。
- 运行时和工具配置摘要；能力不支持时明确拒绝而非静默改变配置。
- 通用 lifecycle conformance suite，所有 Driver 必须执行相同失败注入集。

### 验收

覆盖 I03/I05/I06/I12/I14 与 F03/F07/F08/F19/F20/F28。模拟可忽略取消、启动握手失败、事件断开、退出延迟及限流的后端；用结构化结果区分它们。版本能力探测不能触发真实业务请求。

### 可直接下发的任务

> 你负责 W03 通用 Driver 生命周期与错误。统一现有后端的启动回滚、消息投递、取消、强制停止、退出确认、错误和用量接口，配合 W02 Host 持有它们。先修每条错误出口的资源归属，再建立所有后端共用的 conformance tests。保留完整诊断引用，明确未知执行，禁止以概括字符串替代错误类别。不要改变模型、业务提示词或业务结果判定；共享 runtime 接线交 W00 合并。

## 6 W04 持久操作 结果交付与恢复

### 职责与文件归属

负责操作管理、待发送命令、结果回执、delivery outbox 和 Reconciler。在冻结事务接口上实现，避免与 W01 同时重写 `store.rs`。新增模块的布局交 W00 确认，HTTP handler 以小型接线差异交付。

### 必须交付

- 复用既有异步启动，将 stop、message、result 纳入可查询操作。
- 同操作、同 command、同 submission 的重复请求返回原回执；参数变化冲突。
- 持久未知状态、recovery job、下一次检查及人工处理责任。
- 结果验收与 task 结算的事务边界；可信插件验收契约不能由模型字段绕过。
- 逻辑结果和物理执行分别收口；结果已接受、进程未退出时依然可见并受控。
- 同步兼容等待有界，等待超时不隐式取消；返回 202 不代表已完成。
- 避免提交客户端等待自己退出的死锁；提交回执先返回，再执行收尾。
- 基础设施恢复、传输重试和业务重规划之间的预算及责任边界。

### 验收

覆盖 I01 至 I09/I11/I12/I14 与 F01 至 F08/F14 至 F18/F22/F25/F26/F29。使用每个持久化边界的 crash hook 检验“外部动作已发生但回执尚未持久化”，不得仅覆盖请求前失败。

### 可直接下发的任务

> 你负责 W04 操作、交付与恢复闭环。复用已有 worker start ledger，在 W01 存储接口和 W02/W03 执行契约上实现异步 stop/message/result、持久命令回执、结果提交去重、outbox 和对账责任。必须区分业务结果与物理执行状态，未知效果不得盲目重派，提交成功但响应丢失不得重新跑业务。交付各崩溃窗口的测试、旧同步 API 兼容和共享 server/runtime 的最小接线差异。

## 7 W05 资源准入 公平性与同机预算

### 职责与文件归属

负责准入策略、资源保留、释放、启动速率和同机预算协调。复用已有启动准入，不与插件资源账本双重决定物理容量。数据库结构交 W01；调度与策略可使用独立 admission 模块。

### 必须交付

- 会话、启动、执行、账号、工具、控制恢复资源分别记账。
- 未知执行和停止未确认的保留占用；转入隔离池不能减少总体保护额度。
- 所有容量认领事务化；执行退出后幂等释放，不使用按时间盲清。
- 公平调度、老化、账号冷却、启动速率、有界重试及控制恢复预留。
- 多 daemon 共用机器时的单一预算协调与重启对账；协调服务不可用时停止新准入，停止入口保持可用。
- 准入拒绝的原因、next-check 和唤醒事件，可区分真实容量不足与依赖阻塞。
- 配额变化只影响新准入，不无条件中断活动执行。

### 验收

覆盖 I01/I06/I11/I12/I13/I14 与 F05/F08/F18/F20/F21/F22。证明不存在任一层无限等待导致恢复操作饥饿；多 daemon 测试必须观察真实总保留量，不仅检查各自局部计数。

### 可直接下发的任务

> 你负责 W05 资源准入和调度。以真实执行及未知执行占用为基础，统一会话、启动、执行、账号、工具与恢复额度，复用现有事务队列，补启动速率、公平性、局部冷却和同机预算协调。所有释放必须依据 W02/W04 的退出或未启动证明。不得提高并发来掩盖占位问题，不得按租约年龄清理不确定执行。交付满载、限流、多 daemon、恢复预留与账本重建测试。

## 9 W07 CLI 桌面 移动端与插件兼容
