# Rust daemon 功能与 shell 生命周期对齐

基准：master `53aec26`；实施起点 `bbba795`。交付目标是 Rust daemon + 现有 Electron/TS 桌面，不是同时切换原生 Rust 桌面或迁移全部旧历史。本轮保留此前未提交的 Agent/前端/进度改动，不修改日常运行中的 daemon。

## shell 生命周期

每个生产 PTY 由独立 `terminal-host` 进程持有。daemon 管理会话元数据与检查点，宿主持有实际 PTY、实时屏幕和有界输出事件。两者通过带独立 token 的 loopback HTTP 通信；身份含会话 ID 和宿主协议版本。启动参数和环境只经 stdin 传输，不写入连接描述文件。宿主使用数据目录中按内容哈希固定的可执行副本，应用目录更新不会覆盖旧宿主映射的程序；副本校验失败会拒绝使用，不覆盖已存在的版本。

| 动作 | 行为 |
| --- | --- |
| 断开/重启桌面 | 不结束宿主及 shell；原有游标可以继续读取。 |
| 正常停止 daemon | 分离控制/持久化任务，不结束已建立的独立 PTY。 |
| daemon 被强杀 | 宿主继续持有 shell、变量、后台任务、输出及尺寸。 |
| 重启 daemon | 从活跃租约找到宿主并鉴权重连，不执行原 shell 命令，不创建重复进程。 |
| 宿主仍持锁但无法连接 | 启动失败并保留它；不擅自宣布死亡或另起 shell。 |
| 显式结束会话 | 结束该 PTY 管理的进程组，持久化退出状态/输出，释放宿主和临时凭据。 |
| daemon 离线时 shell 退出 | 宿主保留退出码与输出；重连后归档，确认落库后释放。 |
| 宿主异常丢失 | 活跃会话标记失败，保留已提交的恢复窗口；不伪造运行状态或重放命令。 |
| 恢复游标超过现有水位 | 返回重同步要求，不让客户端陷入持续 400 错误。 |

配套改动：

- macOS 结束 PTY 时先关闭 master/reader 句柄，再回收子进程，避免卡在 tty 退出阶段。
- daemon 的随机端口在可用时优先复用，显式指定的端口不变；被占用时可重新分配。`prospero` 命令在 daemon 注入的 discovery 模式下，每次从 `PROSPERO_HOME` 读取最新连接，避免存活 shell 继承旧 HTTP 端口而失联。旧的显式 HTTP 覆盖方式仍支持。
- 宿主保留输入背压与“不重试可能部分执行的输入”错误语义；HTTP 回执不确定时按非重试输入失败处理。
- 保留 16 个活跃 PTY 的既有上限；连接数、输入队列、输出保留窗口与检查点并发保持有界。新增每 PTY 一进程的开销，不能沿用旧 daemon 单进程 RSS 数据宣称整体性能达标。
- 健康声明按实际是否启用独立宿主报告 PTY persistence，生产后端增加 `terminal.detached-host.v1` 能力。

## 验证

结果基于 macOS arm64 工作树，保留了此前未提交的改动；不是 Windows/Linux 实机结果。所有 daemon/宿主测试使用临时数据目录；没有切换本机旧 daemon。

- Rust 库回归覆盖三引擎正向、非法工具、错误回执、取消清理及账号租约释放。
- 真实 daemon 生命周期测试覆盖 SIGKILL/正常重启、同 PID 与内存变量、尺寸继续变化、控制命令重新发现连接、显式关闭、离线退出、私有鉴权、非重试输入背压。
- Windows ConPTY 重启/关闭用例已加入源码，须由 Windows runner 验证；本机结果只代表 macOS arm64。
- 桌面桥集成使用真实 Rust daemon/宿主与假 CLI/模型服务验证账号、模型、控制、历史与终端。
- 全量检查结果与跳过项见本文后续验证记录，不把默认 ignored 的真实 CLI 测试算作普通测试通过。

## 切换边界

1. 现有旧 daemon 的 PTY 不能把内核句柄直接转交给这个新宿主。保留旧 shell 的要求继续有效：本轮只提交代码，不覆盖或停止日常 daemon。新版机制从新版 daemon 创建的 shell 开始生效。
2. 结构化 Agent 的进程生命周期不等同于 PTY；本轮没有承诺在 daemon 被强杀后继续原来的结构化流式调用。
3. 终端快照兼容范围和有界历史保留仍有限；宿主存活不等于无限输出日志或所有终端扩展均能完整冷恢复。
4. 宿主执行文件按版本保留在数据目录；本轮未自动清理旧版本的程序副本，避免删除仍由旧宿主使用的程序。
5. 完整旧历史迁移、所有平台发布产物、真实供应商账号/长跑及移动端全面验收仍属于替换 master 的发布门槛。此次功能和 PTY 改动不意味着可以直接移除 TS 回退路径。
