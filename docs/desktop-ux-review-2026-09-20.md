# 前端体验检查与第一版优化

检查范围：当前 Electron 桌面的新建会话、概览、工作台工具入口和通用设置。先检查日常安装版界面，再用合成项目、账号和模型源的独立窗口验证改版。没有重启日常客户端或 daemon，也没有修改实际账号、权限或会话。

## 本轮发现并调整

| 问题 | 影响 | 第一版调整 |
| --- | --- | --- |
| 在当前项目点击新建，默认选择另一个工作区 | 容易建错位置，用户需要重复选择目录 | 优先使用当前本地会话所属的已注册工作区；显式从某项目新建仍优先。支持 worktree 与嵌套项目。 |
| 工作区下方只说“项目根目录与持久上下文” | 不能帮助确认实际执行位置 | 显示真实路径，长路径可悬浮查看。 |
| “Code Agent / Pane 类型 / CLI / 独立 Profile”等混杂 | 同一概念在不同连接方式中叫法不同 | 统一为 Agent、会话类型、账号；连接入口改为“本机账号 / API 配置”。 |
| 共享模型流程把 Agent 和会话类型分散在上下两处 | 需要反复上下查看，弹窗偏长 | 将两者并排，与本机账号流程一致。 |
| 模型名称出现“Claude · Claude” | 重复信息干扰选项辨认 | 展示名称只补充一次引擎后缀；不改模型、路由 ID 或存储名称。 |
| 主流程直接解释协议、凭据和执行引擎实现 | 核心选择被说明文字打断 | 连接技术细节折叠；保留“模型源更新不会改变已有会话”的重要说明。 |
| 权限选项直接显示 Strict / Standard / YOLO | 需要理解内部术语才能判断风险 | 改为严格确认、标准确认、自动批准（高风险），保留原值、默认策略和风险说明。 |
| “终端”图标实际打开系统终端 | 与应用内 shell 入口混淆 | 明确为“外部终端 / 在系统终端打开工作区”。 |
| 分页正文的复制按钮没有范围说明或结果反馈 | 容易以为复制了全文；失败缺少提示 | 标注“复制当前页”，显示成功/失败，读取中禁用，避免复制旧页。 |
| 设置和输出详情向普通用户解释 daemon、托盘进程、渲染进程持久化 | 信息与当前操作关系不大 | 改为用户能直接理解的启动、后台运行、选择与复制说明。 |

## 后续建议（第 1、2 项已在第二轮完成核心调整）

1. **概览待办分组**：审批、提问和失败事项目前汇总到同一计数。可按阻塞程度分组，并提供当前工作区筛选；不能直接隐藏尚未处理的真实事项。
2. **长标题的阅读路径**：概览卡片宽度有限，自动生成的任务标题和内部标识占据摘要。建议先展示项目/任务名称与事项类型，完整原文可展开。
3. **导航语义**：“运行”与“工作台”的区别不够直观，可以评估“任务编排”等名称；这涉及全局用词，宜统一调整。
4. **空账号与空模型源**：错误/空状态应直接提供去配置的入口，并在返回后保留工作区选择，减少“关闭弹窗 → 找配置页 → 重新新建”的往返。
5. **已归档会话的标签**：侧栏收起后，已有顶部标签仍可能保留，需要明确“归档”和“关闭标签”的关系。

预览中先打开“当前项目会话”，再点击“新建会话”，即可检查默认工作区；切换“共享模型源”可查看简化后的选择流程。预览使用临时项目和独立用户配置，可从 Electron 应用菜单退出（macOS 为 ⌘Q）。


## 第二轮：待办分组与工作台顶部

- 概览和收件箱统一按请求数计数，分别展示待确认、待回答、失败与阻塞。同一会话同时有权限请求和问题时，分别出现在对应分类。已结束会话的残留计数不再显示为待办。
- 收件箱提供分类筛选；离线提示始终可见。审批卡片以任务名称和项目为摘要，完整请求、原因与处理按钮一起展开；失败任务可展开完整标题和说明。
- 顶部标签优先显示自动标题中的项目/主题，保留自定义名称。同名会话使用序号区分。固定可读宽度并横向滚动，悬停提供完整名称与路径。
- 会话工具栏合并重复的标题与项目路径。正常连接时收起“实时终端”状态条，异常提示使用浮层，避免连接状态变化触发终端高度改变。
- 验证：475 项桌面测试、类型检查、构建通过；隔离原生窗口检查了分组、分类筛选、审批原文展开和工具栏布局。多标签命名由测试覆盖；日常旧 shell 未重启，此轮未覆盖正式安装版。
- 合成待办和 shell 预览：构建后运行 `node_modules/.bin/electron apps/desktop/scripts/preview-ux.cjs --attention`。预览拒绝真实写操作。

## 终端拖选时的缓存开销

终端旧输出模式会周期性同步序列化最多 10,000 行恢复缓存，与选区绘制竞争渲染主线程。本机使用 xterm headless + SerializeAddon、160 列/48 行、10,000 行混合中文与彩色 ASCII 输出，连续六次序列化耗时为 107、68、68、66、81、62 ms。这是合成缓存开销，不是实际拖选延迟，也不能单独证明用户卡顿的唯一原因。

修复将周期缓存延后到没有拖选手势、滚动或键盘输入且浏览器空闲时执行；同一输出游标和终端尺寸不重复序列化。保留完整缓存行数和原来的卸载保存逻辑，不暂停终端输出或改变选区语义。事件模式仍不生成此类周期缓存。

480 项桌面测试、类型检查和构建通过；新增测试覆盖长按拖选、idle 排队后的新手势、取消手势、滚动和输入、缓冲区未稳定重试与销毁取消。该修复尚未覆盖本机正式安装版，也尚未做正式版拖选手感验证。旧 shell 与 daemon 保持运行。
