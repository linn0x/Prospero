# Daemon 控制面性能优化（2026-09-20）

本轮覆盖调度读取、插件服务查询、状态投影和终端持久化。当前日常 daemon 与旧 shell 按用户要求保持运行，本轮没有切换日常进程。

## 已修改

- 调度列表读取移到阻塞工作线程；缓存已解析的 TOML，按文件修改时间、大小以及 Unix inode/ctime 失效。缓存最多 512 项、8 MiB 源文件字节；路径验证和依赖当前时间的默认值仍逐次计算。本进程写入与删除立即使对应缓存失效。
- 插件列表一次读取状态文件，按一致的观察结果生成视图。未变化的状态不再因查询而更新；真实变化最多批量写一次，并在写入时比较观察版本，避免覆盖并发健康/重启更新。文件扫描和持久化在阻塞线程执行。服务 PID 固定保存在运行对象中，查询不再等待停止进程时持有的 child 锁。
- 状态文件投影的密集通知合并到最短 100 ms 间隔，保留每秒心跳。会话摘要/事件水位未变时复用有界会话窗口；文件写入移到阻塞线程。注意力通知不持有投影写锁等待网络。
- 健康接口的 relay 文件读取移到阻塞线程，降低并发文件扫描对其他请求的影响。
- 终端检查点从首次输出变化开始合并 250 ms。原逻辑在新输出到达时跳过合并等待，导致持续输出时频繁生成快照及写 SQLite。退出时仍走最终归档事务。空闲判定只构造末尾需要的屏幕行，避免先复制整个视口。

## 三轮测量

脚本：`tools/perf/daemon-control-benchmark.mjs`。
原始结果：`tools/perf/daemon-control-macos-arm64-2026-09-20.json`，含硬件、系统、Node 版本和前后二进制 SHA-256。

| 隔离场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 300 条暂停任务，每条约 4 KB prompt；列表查询 p95 | 28.10 ms | 17.57 ms |
| 6 个上述列表请求并发时，健康接口 p95 | 51.82 ms | 6.11 ms |
| 20 个私有 sleep 假服务；插件状态查询 p95 | 36.84 ms | 1.52 ms |
| 每轮 20 次插件查询中造成状态文件重写的请求数 | 20 / 20 | 0 / 20 |

表内延迟为**三轮各自 p95 的中位数**，不是将样本合并计算的全局 p95。调度列表优化后三轮 p95 为 32.30、17.57、16.97 ms，其中一轮未优于基线；机器其他负载没有固定，不能据此承诺生产延迟。测量包括 Node 客户端接收和 JSON 解码，不包含桌面绘制、真实 Agent 或外部模型服务。

复现（在仓库根目录）：

```sh
node tools/perf/daemon-control-benchmark.mjs --binary /path/to/prosperod-rs --scenario schedules --trials 3 --output /tmp/schedules.json
node tools/perf/daemon-control-benchmark.mjs --binary /path/to/prosperod-rs --scenario plugins --trials 3 --output /tmp/plugins.json
```

脚本为每轮创建独立数据目录和子进程专用调度配置，任务全部暂停，插件仅使用手动启动的 sleep 假服务，退出时停止假服务并清理临时目录。插件假服务场景目前仅支持 Unix。

## 验证与边界

- 64 项 daemon 库测试通过。
- 63 项 CLI、HTTP、查询、远程协议、数据库 worker、终端运行时测试通过。
- 新增验证覆盖：TOML 缓存复用与外部编辑/删除、缓存上限、查询插件不写盘、批量更新避免覆盖并发健康状态、投影限频与心跳、会话变更使投影失效、持续输出检查点有界频率。
- 格式、Clippy 检查通过。未改变协议字段或放宽既有性能阈值。
- 仍需独立评估账号 CLI 探测、大 DAG/协作扇出、快照持锁时长及多平台高并发；本轮数据不能代表这些场景已优化或验收。
